# Unloop

Локальное Android-приложение для ограничения бесконечного просмотра Reels и Shorts. Android 10+, русский интерфейс, Kotlin и Jetpack Compose.

## Что реализовано

- Индивидуальная защита Instagram и YouTube и общий выключатель.
- Нейтральные накладки на распознанные кнопки Reels/Shorts в нижней навигации. Накладки перехватывают нажатия. Встроенные карточки рекомендаций в общей ленте не скрываются.
- Первый ролик по прямой ссылке остаётся доступен. При обнаружении перелистывания Unloop выполняет «Назад». Если через 500 мс тот же плеер остаётся открыт, выполняется «Домой».
- Прокрутка распознанной панели комментариев не вызывает выход. Неизвестные экраны не блокируются.
- Экранное время сегодня, недельный график и приложения с наибольшим временем через Usage Access.
- Локальный счётчик выполненных возвратов, удаление истории, хранение событий до 30 дней.
- Инструкции по включению системных оттенков серого. Приложение не выдаёт ручной режим за автоматический переключатель.
- Отдельное согласие перед подключением Accessibility и возможность его отозвать.

**Статус 0.1.1:** проект переименован из Still в Unloop; текущий дизайн сохранён. Локальный APK для arm64-v8a собран инструментами Kotlin/Android SDK из исходников с использованием кешированных зависимостей, подпись и выравнивание проверены. Все 23 модульных теста прошли. Стандартная сборка Gradle и lint в среде агента ограничены запретом локальных соединений; повторная сборка предусмотрена в CI. Сигнатуры интерфейса остаются экспериментальными: их нужно проверить на конкретных версиях Instagram/YouTube. Синтетические тестовые деревья не подтверждают совместимость с реальными приложениями.

Android-идентификатор `app.still`, имя базы и внутренние компоненты сохранены для совместимости с установленной версией. Видимые названия приложения и сервиса — Unloop.

## Публикация на GitHub

В обычном терминале Mac с настроенным доступом GitHub CLI:

```sh
cd /Users/askar/Projects/Unloop
./scripts/publish.sh
```

Скрипт проверяет доступ, запускает стандартную сборку и проверки, создаёт приватный репозиторий `<ваш аккаунт>/unloop`, отправляет исходники и тег `v0.1.1`. Тег запускает GitHub Actions: после успешных проверок APK `Unloop.apk` и `SHA256SUMS` появляются в GitHub Releases. Если существующий remote отличается или тег указывает на другой коммит, скрипт останавливается и не перезаписывает их.

Локальная сборка текущей версии находится в `dist/Unloop.apk`; каталог `dist` не коммитится. Ключи подписи, настройки IDE, SDK и кеши также исключены из Git.

## Сборка APK

Нужны JDK 17, Android SDK Platform 35, Build Tools 35.0.0 и доступ к Google Maven, Maven Central и сервису распространения Gradle. Проект использует AGP 8.9.2, Kotlin 2.1.20 и Gradle 8.11.1. JDK 25 для этой конфигурации не подходит.

Проще всего открыть эту папку как проект в Android Studio, установить SDK 35 и выбрать Gradle JDK 17. При необходимости указать SDK в неотслеживаемом `local.properties`:

```properties
sdk.dir=/absolute/path/to/Android/sdk
```

На macOS/Linux:

```sh
export JAVA_HOME=/absolute/path/to/jdk-17
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Android Studio создала стандартный Gradle Wrapper; его конфигурация закреплена на Gradle 8.11.1. При первом запуске `./gradlew` скачает эту версию. Если Gradle 8.11.1 уже установлен, можно использовать `gradle` вместо `./gradlew`. Для Windows используйте Android Studio или `gradlew.bat`.

Результат успешной сборки:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Debug APK подписывается локальным отладочным ключом Android. Для обновления уже установленного APK используйте ту же среду сборки и ключ. APK из разных CI-запусков может иметь другой ключ и потребовать переустановки с потерей локальной истории. Для личного постоянного использования предпочтительна локальная сборка с сохранённым ключом.

## Установка и подключение

1. Установите APK обычным способом или через `adb install -r app/build/outputs/apk/debug/app-debug.apk`.
2. В Unloop откройте «Защита» → «Подключить защиту», прочитайте объяснение доступа и подтвердите согласие.
3. В специальных возможностях Android включите сервис Unloop. Для установленных вручную APK Android может потребовать разрешить ограниченные настройки в системных сведениях о приложении. Названия пунктов зависят от телефона.
4. На вкладке «Сегодня» разрешите доступ к статистике использования. Это отдельный доступ, защита не требует его для работы.
5. Откройте Instagram/YouTube и проверьте сценарии ниже. Не считайте защиту рабочей до этой проверки.
6. На вкладке «Экран» следуйте инструкции для системных оттенков серого. Расписание настраивается средствами телефона, если он его поддерживает.

Если производитель останавливает сервис в фоне, проверьте его состояние в специальных возможностях и настройках энергосбережения. Unloop не запрашивает исключение из энергосбережения автоматически.

## Как устроен проект

- `core`: независимые от Android правила распознавания и подсчёт времени по временной шкале.
- `protection`: Accessibility-сервис, временные снимки структуры экрана, накладки, возврат и текущий статус распознавания.
- `data`: DataStore для настроек, Room для событий прерывания, адаптер Android UsageEvents.
- `MainActivity` / `MainViewModel`: три экрана Compose, разрешения, согласие и состояние интерфейса.

Детекторы разделены по пакетам `com.instagram.android` и `com.google.android.youtube`. Кандидаты идентификаторов находятся в `core/Detection.kt`. Новую сигнатуру нужно добавлять только после проверки, что она отличает полноэкранный плеер от карточки в обычной ленте и комментариев. Маски используют границы узлов; постоянных координат для конкретной модели телефона нет.

Публичного сетевого API и сервера нет. Внутренний интерфейс детектора: `detect(packageName, nodes, screen) → Detection`; решение о выходе принимает `ScrollGuard`. Android-зависимые типы в эти правила не передаются.

## Ограничения

- Официальных API для удаления кнопок внутри Instagram/YouTube нет. Маска визуально закрывает элемент, а не меняет разметку приложения. Цвет накладки следует системной теме и может отличаться от темы соцсети.
- Обновления приложений, эксперименты с интерфейсом, закрытые Accessibility-узлы и особенности производителя могут нарушать распознавание. При неизвестной структуре Unloop не накладывает маски наугад.
- Событие прокрутки поступает после её начала: следующий ролик может кратко появиться. Начальная пауза 700 мс защищает от событий инициализации плеера; очень быстрый свайп при входе может быть пропущен.
- Автоматический переход к следующему видео не всегда отличим от ручной прокрутки. Не гарантируется работа в браузерах, клонах приложений, PiP и разделённом экране.
- Панель с нераспознанными комментариями требует проверки на устройстве. Распознанная крупная панель комментариев временно отключает выход при прокрутке.
- UsageEvents — оценка активности. При пересекающихся окнах общее время считается по объединению интервалов, время отдельных приложений может пересекаться. Публичный API не позволяет различать экземпляры одной и той же Activity; неполная история и редкие последовательности жизненного цикла могут влиять на точность. История за прошлые дни доступна только в пределах сохранённых Android событий.
- Число прерываний — число принятых Android команд возврата/выхода, а не оценка «сэкономленного времени».
- Самостоятельное отключение сервиса или удаление приложения не запрещается. Приложение рассчитано на добровольное использование.

## Приватность

В манифесте нет разрешения INTERNET, аналитики и рекламных SDK. Деревья Accessibility, описания элементов, содержимое видео и переписка не записываются и не логируются. Снимки узлов существуют только в оперативной памяти во время распознавания.

DataStore хранит переключатели и согласие. Room хранит только имя пакета и время выполненного прерывания. Старые записи удаляются при подключении сервиса и записи новых событий. Системная история использования читается для отчёта, но не копируется в локальную базу. Резервное копирование приложения отключено.

Кнопка удаления истории очищает Room, но не настройки и не системную историю Android. При отзыве согласия маски удаляются и обработка интерфейса прекращается; сам сервис можно отключить в Android.

## Проверки

```sh
# 23 модульных теста, Android lint и сборка
./gradlew testDebugUnitTest lintDebug assembleDebug

# Один тест Room на подключённом эмуляторе/устройстве; база только в памяти
./gradlew connectedDebugAndroidTest
```

Модульные тесты проверяют маски навигации, отсутствие масок на обычных элементах, отличие inline-плеера от полноэкранного, комментарии, первое перелистывание, повторные события, повторный вход; подсчёт пересекающихся Activity, блокировку экрана, полночь, смену длительности суток и перезагрузку.

GitHub Actions (`.github/workflows/android.yml`) подготовлен для unit-тестов, lint и сборки debug APK с сохранением отчётов. Workflow запустится после размещения исходников в GitHub; из текущей среды он не запускался. Инструментальный тест Room требует отдельного устройства/эмулятора и не входит в этот CI job.

Ручная матрица и текущие результаты — в [TESTING.md](TESTING.md). Только прохождение этой матрицы позволяет записать конкретную версию приложения как проверенную.

## Следующие функции

После подтверждения основной механики: дневные лимиты, расписание фокуса и пауза перед открытием соцсетей. Они не включены в эту версию. У вмешательства с короткой паузой есть [исследовательская основа](https://doi.org/10.1073/pnas.2213114120), но индивидуальный результат не гарантирован.

При подготовке к Google Play отдельно проверить актуальные [правила Accessibility API](https://support.google.com/googleplay/android-developer/answer/10964491), оформить декларацию и описание использования. Публикация в магазин в текущую задачу не входит.
